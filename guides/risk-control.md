# 风控：能降的降下来，降不掉的说明白

先说结论：**第三方协议端的封号风险无法归零，只能降低概率并把损失控制在小号上。**

这份文档做两件事：把能做的措施全部列出来（都已实现或可配置），以及说清做不到的部分。

## 一、风险从哪来

腾讯判定"异常"主要看行为特征，不是看你连了什么库。常见的触发点：

| 特征 | 说明 |
|---|---|
| 秒回 | 人不会 0.3 秒就回一大段 |
| 高频固定节奏 | 每分钟精确发 N 条，间隔规律 |
| 单条消息过长 | 一次甩出几百字，不像手机打字 |
| 长期不活跃后突然高频 | 沉寂一个月突然每天几百条 |
| 一上线就群发 | 主动私聊大量陌生账号 |
| 异地/多设备频繁切换 | 同一号在北京和上海来回登 |
| 官方客户端与协议端同时在线 | 会互相踢，且明显异常 |
| 只发不收 | 从不读消息只往外发 |

## 二、已经做了的（配置层）

### 1. 限流收紧

```json
"platform_settings": {
  "rate_limit": { "time": 60, "count": 10, "strategy": "stall" }
}
```

原来是 `count: 30`（一分钟 30 条），收到 **10 条/分钟**。
超出的消息会被排队而不是丢弃（`stall`），不会丢内容。

一对一私聊，一分钟 10 条已经是很快的节奏了。

### 2. 分条发送 + 打字间隔

```json
"segmented_reply": {
  "enable": true,
  "interval": "1.2,2.6",
  "words_count_threshold": 300,
  "regex": ".*?[。？！~…\n]+|.+$"
}
```

一整段变成几条发出去，条与条之间停 1.2–2.6 秒——跟人打字速度接近。

**注意** `words_count_threshold` 是上限，超过它反而不切，别设太小。

### 3. 表情包频率

`generation.emotion.probability` 设成 7（约 1/14）。
不设的话每轮都想配图，又密又假。

## 三、已经做了的（代码层）

新插件 `astrbot_plugin_humanlike` 做四件事：

| 动作 | 为什么 |
|---|---|
| 收到消息先 `mark_private_msg_as_read` | 真人会点开消息，从不读只发很可疑 |
| 回复前随机停顿 0.6–1.8 秒 | 打掉"秒回"这个最明显的机器特征 |
| 尝试 `set_input_status`（正在输入） | 让协议端表现像客户端；参数不兼容会安静跳过 |
| 打字状态再停 0.3–0.9 秒 | 模拟"正在打字"到"发出去"的过程 |

配置项：

```json
{
  "min_delay": 0.6,
  "max_delay": 1.8,
  "mark_read": true,
  "typing_indicator": true
}
```

代码：`src/astrbot_plugin_humanlike/`

## 四、必须靠行为习惯的（技术管不了）

这几条只能靠你自己：

1. **单号单端。** 同一个 QQ 号不要同时挂官方手机客户端和 NapCat，会互相踢，且是明确异常信号
2. **新号先养。** 注册后先正常用几天（加好友、发动态、进群），别当天就挂机器人
3. **固定出口 IP。** 别频繁换服务器/换地区
4. **不做主动群发。** 不主动私聊陌生号、不批量加好友
5. **别在深夜高频。** 凌晨三点连续聊两小时，人也不会这样
6. **别刷屏。** 单次回复别超过三四条
7. **小号专用。** 不绑重要东西，不做支付、不绑主号好友

## 五、做不到的，说清楚

| 事项 | 状态 |
|---|---|
| 完全避免封号 | ❌ 做不到。协议端本质是模拟客户端，腾讯随时可能调整检测 |
| 保证不掉线 | ❌ 做不到。踢下线、改密码、风控都会导致要重新扫码 |
| 被判定后申诉 | ❌ 基本无门。协议端本身不在用户协议允许范围内 |
| 用主号"应该没事" | ❌ 绝对不要。主号一旦被处置不可逆 |

**现实的心理预期**：小号 + 低频 + 像人地聊天，能撑很久；但它是一颗随时可能响的雷，重要的事情不要挂在上面。

## 六、出事了怎么办

### 掉线

```bash
systemctl status napcat
# 重新扫码
# 二维码位置：<NapCat目录>/opt/QQ/resources/app/app_launcher/napcat/cache/qrcode.png
```

systemd 会自动重拉进程，但**扫码必须人工**。

### 被限制登录 / 要求验证

按手机 QQ 提示走（短信验证、好友辅助）。别用自动化工具硬闯，会让判定更重。

### 号被封

新建小号，把 `cmd_config.json` 里的 QQ 号相关项换掉，重新扫码。
人格、插件、记忆都在服务器上，不用重来。

### 建议的兜底

- 保留一份配置备份（`cmd_config.json`、`data_v4.db`、插件目录）
- 记录当前小号的注册信息，方便换号时对照
- 别把机器人当成唯一入口——重要提醒还是自己设闹钟

## 七、自查清单

```
[ ] rate_limit 收到 10 条/分钟以内
[ ] segmented_reply 开着，间隔 ≥1 秒
[ ] humanlike 插件已装，日志有 loaded
[ ] 表情包概率不是 100
[ ] 白名单只放了自己（或极少数人）
[ ] 没有同时挂官方客户端
[ ] 小号不是主号、没绑重要信息
```

前六条是配置能保证的，最后一条只能你自己保证。
